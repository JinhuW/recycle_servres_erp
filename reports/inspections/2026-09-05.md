## Root-cause analysis

Not applicable — no error data was available to analyze. The only
code-level findings this run are descriptive, not diagnostic: areas
touched by the four releases merged to `main` since yesterday, listed for
reference if a future run regains Railway access and needs to correlate
errors against this deploy window:

- `apps/frontend/src/components/SerialChipsField.tsx` /
  `apps/frontend/src/lib/serialField.ts` (v1.126.0 → v1.126.1, RS-023/
  RS-025) — serial-number chip entry for order lines. v1.126.1 fixed a
  data-integrity bug introduced hours earlier in v1.126.0: the field
  decided which characters were still mid-typing by checking whether its
  value *ended with* the pending text, so a scanned serial ending in the
  same characters as the half-typed input (`2` typed, `SNX0012` scanned)
  had its tail stripped and was stored one character short
  (`SerialChipsField.tsx`, now fixed via `readPending` in
  `serialField.ts`, with a regression test in `serialField.test.ts`).
  Already fixed before this report; flagged only so a future log review
  can check for any `SNX...`-shaped serial values recorded during the
  ~10-hour window v1.126.0 was live on `main` (2026-09-04, per commit
  timestamps `6a4e395` → `70fefcb`) that look truncated.
- `apps/backend/src/routes/*` payments/settlement paths (v1.127.0,
  RS-024) — "money that has not settled yet says so"; adds a pending/
  unsettled state to payment display. Purely additive per the ticket
  title; no schema migration shipped with it.
- Payments grouping logic (v1.128.0, RS-026) — a pending payment leg now
  groups with its settled sibling. Also additive, no migration.
