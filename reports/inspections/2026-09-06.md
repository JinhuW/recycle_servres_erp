## Root-cause analysis

Not applicable to this routine's own findings — no error data was
available to analyze independently this run. For reference, the RS-027
fix itself is worth noting since it changes what *future* runs of this
routine will be able to see, once access exists:

- `apps/frontend/src/lib/beacon.ts` (new) / `apps/frontend/src/lib/api.ts` /
  `apps/frontend/src/lib/auth.tsx` / `apps/frontend/src/lib/timing.ts` /
  `apps/frontend/src/lib/errorToast.ts` (v1.128.1, RS-027, on `dev`, not yet
  on `main`) — client timing/error beacons previously dropped their report
  on the floor if they 401'd before a session existed (`rawFetch` neither
  refreshes nor retries — `api.ts:207-229`). That silently discarded 7 of
  91 timing reports and 1 of 2 ever-sent client-error reports in the
  reference window, biased toward the worst loads (cold, logged-out). A
  401'd report is now held and re-sent once an `auth:established` event
  fires. Once this ships to `main`/prod, client-error and cold-load timing
  visibility should measurably improve — worth a note for whichever future
  run of this routine first gets Railway access, since historical
  comparisons across the v1.128.0 → v1.128.1 boundary will show a jump in
  reported client-error/timing volume that is instrumentation coverage
  improving, not a new regression.
- RS-027 also surfaced two **out-of-scope, infra-config** items (not code
  bugs, so not actioned in that PR) that remain open per the ticket and are
  worth this routine flagging again until closed: (1) the production PayPal
  app is missing the **Disputes** permission (8× `403 NOT_AUTHORIZED` on
  `GET /v1/customer/disputes` in the reference window) — a PayPal dashboard
  toggle, separate from Transaction Search; (2) `SHIPPO_API_TOKEN` and
  `SHIPSAVING_APP_KEY`/`_SECRET` are unset in production, so shipment
  tracking never advances on its own and labels stay canned demo data (the
  boot banner announces this every restart). Neither was verified by this
  routine directly — both are carried over from RS-027's own log read.
