  - `74e1cf4` (PR #88, merging PR #87, 2026-08-05T14:15:34Z) — **v1.50.1**.
    Fixes `apps/backend/src/mcp/server.ts` (`tools/call` error handling):
    previously every in-tool failure (e.g. a market-price write for a
    part number with no matching `ref_prices` row) was reported through
    `rpcErr` as a JSON-RPC protocol error, which ChatGPT's connector client
    surfaced as a transport failure rather than a recoverable tool result —
    causing the model to conclude the write tool was disabled and stop
    retrying for the rest of the session. The fix moves in-tool failures
    (`not_found`, etc.) into `isError` tool results per the MCP spec, keeping
    only `unknown tool` / `insufficient_scope` / parse errors as JSON-RPC
    errors, and adds tool annotations (`readOnlyHint`, `destructiveHint`,
    `openWorldHint`) so read-only tools stop being mislabeled as destructive
    writes in client UIs. Touches `apps/backend/src/mcp/tools/market.ts` and
    `apps/backend/src/mcp/tools/sellOrders.ts` as well.
  - This is presumed deployed to Railway prod already (tracks `main` per
    `CLAUDE.md`), but **deployment status itself is unverified** — this
    routine cannot distinguish "deployed and healthy," "still building," or
    "failed to deploy." Since the change is scoped to `/api/mcp` tool-call
    error paths (a Bearer-only, CSRF-exempt surface per `CLAUDE.md`'s "MCP &
    OAuth" section), the natural first check once Railway access is restored
    is whether `tools/call` requests are erroring or succeeding post-deploy.
