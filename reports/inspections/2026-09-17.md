**RS-057 in detail** (already root-caused in [`docs/debug-notes/2026-09-16-bare-stop-handler-aborts-every-request.md`](https://github.com/JinhuW/recycle_servres_erp/blob/dev/docs/debug-notes/2026-09-16-bare-stop-handler-aborts-every-request.md) on `dev`, not present on this branch): RS-053 (v1.144.0, shipped 2026-09-15 21:23 UTC) deleted a local `stop` helper in `DesktopPayments.tsx` as apparently-unused, but the action rail's `onClick={stop}` kept referring to it — which TypeScript silently resolved to the DOM global `window.stop()`. Every click on the rail's action buttons started its POST, then `window.stop()` cancelled all in-flight requests including the one just issued, before the click bubbled up and toggled the row open. This was live on production for roughly **5.5 hours** (v1.144.0 deploy at 21:23 UTC on the 15th to the v1.145.1 fix at 03:05 UTC on the 16th) before being fixed. **This routine cannot confirm from logs whether that window produced elevated error volume in production**, since Railway access was already unavailable when it happened; the debug note describes it as reproduced live by a human operator via the browser's `performance` API, not diagnosed from server logs.

**RS-058 in detail**: the v1.144.1 line-removal guard in `apps/backend/src/routes/orders.ts` refused to delete a PO line whenever *any* non-archived sell order referenced it, regardless of that sell order's status — inconsistent with the archive dialog and stage-revert logic, which both key on the shared "open" status set. The fix (`8033b7bb`) adds `AND so.status = ANY(${openSellStatuses()}::text[])` to the guard query, so Closed and Done sell orders (which already release their line via the `ON DELETE SET NULL` FK added in migration `0127`) no longer block removal. This is a straightforward status-guard correction with an accompanying test update (`orders-remove-line-archived-sell-order.test.ts`) and no migration.

No new migrations landed between yesterday's report and today. `origin/dev` carries one additional release not yet on `main` — **v1.146.0** (`c15c174`, RS-059: dashboard day-precise range brush, cashflow chart, contribution cards) — a frontend/reporting feature with an accompanying shared calendar-helper addition; nothing in its diff touches migrations or status guards, so it is lower priority to verify once access returns.
