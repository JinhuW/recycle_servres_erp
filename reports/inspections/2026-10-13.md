ON CONFLICT DO NOTHING` seeding the `AS` id counter. Pure `CREATE TABLE`/`CREATE INDEX`, no backfill, no data rewrite, no hard-fail guard. Low boot risk.
- **`apps/backend/migrations/0176_bank_tx_sell_order_and_commission.sql` (dev only, v1.257.0, RS-249 — payments link to a sell order or a PO's commission).** Adds `bank_transactions.sell_order_id`, then finds and drops the table's unnamed link/commission CHECK constraints by `pg_get_constraintdef` pattern match (a deliberate choice, per the migration's own comment: `0100` left them unnamed) and re-adds five named CHECKs enforcing "exactly one of order_id/sell_order_id, paired with linked_at and link_kind." No row rewrite — constraints are schema-only — so the risk is a constraint mismatch against existing data rather than a crash: if any already-linked row violates the new `bank_transactions_one_target`/`_linked_at_pair`/`_link_kind_pair` CHECKs, the `ALTER TABLE ... ADD CONSTRAINT` fails at migrate time and the boot fails loudly rather than corrupting data — a safe failure mode, but worth confirming cleanly applied once this reaches `main`, since it isn't deployed to production yet.
- **RS-233 through RS-240, RS-242 through RS-247 (`v1.248.0`–`v1.255.1`)** — no new migrations in this slice beyond `0175`; these are application-logic and UI changes (DDR5 bid-sheet folding, after-sales workflow and UI, pre-release review fixes for v1.247/v1.251/v1.254).
