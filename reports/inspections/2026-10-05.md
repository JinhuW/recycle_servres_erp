## Root-cause analysis

Not performed — there is no log data to triage or trace back into `apps/`/`packages/` source this run. What follows is a read of what shipped to production today, for context on what is now live and unmonitored (from `CHANGELOG.md` on `origin/main`, not just commit subjects):

- **v1.204.0** (RS-164, #491) — the Facebook tracker page gained a live worker browser viewer at `/fleet/watch/<worker>`. The backend relays a WebSocket to the fleet console's VNC endpoint (`vncBridge.ts`, new in this release): the upgrade is replayed as a GET so the proxy-secret gate, session cookie, manager check and a new Origin check all apply, then it mints the facade's single-use ticket and pumps bytes — neither the console token nor the facade credential reaches the browser. This is a new credential-relaying surface with real session hijack/replay blast radius if any of those checks regress; worth a priority read of `vncBridge.ts` and its Origin check once logs are back, since it has had zero production traffic observation so far.
- **v1.207.0 / v1.208.0** (RS-169, RS-166) — desktop sidebar restructuring (second nav level, fold-to-rail). Pure frontend; low backend-error risk.
- **v1.208.1 / v1.208.2** (RS-165, RS-170) — fleet-console facade error reporting and Re-login UX fixes layered on top of v1.204.0's new surface.
- **v1.209.0** (RS-161, #486) — web submissions can now be answered by email from inside the ERP, over SMTP/IMAP against one shared company mailbox (Lark). New migration `0157` (`web_submission_messages`, `mail_sync_state`), new deps (`nodemailer`, `imapflow`, `mailparser`, `html-to-text`). This is a new **outbound path to real customers** — a bug here doesn't just 500, it can mis-send or mis-attribute a reply to a seller. The design has real safeguards worth noting (IMAP is read-only and never marks messages read; incoming answers are matched by reply-to-ERP-sent-message rather than a forgeable WS-id-in-subject; DMARC/sender-mismatch is surfaced in the thread) — but none of it has been observed under real traffic yet.
- **v1.209.1** (RS-175, #502, pre-release review fixes for v1.204.0–v1.209.0) — fixed a real auth-lifetime bug: the VNC viewer's socket was authorized once at handshake and then relayed indefinitely, so a manager who was signed out, deactivated or demoted kept live control of a worker's browser. Now re-checked every minute. Given this shipped same-day as the feature it's patching, and is exactly the kind of session-lifetime bug this routine would normally confirm via logs, it's a good first thing to verify once Railway access is back (watch for the "brief reconnect about once an hour" behavior it introduces, and confirm no regression to "every click refused" that the fix describes replacing).
- **v1.209.2** (RS-173, #501) — added `MAIL_ALLOW_TO` so dev can test the v1.209.0 mail feature without emailing real customers (dev's DB is a nightly copy of prod). Confirms the team is treating v1.209.0's blast radius seriously; also confirms prod is the only environment actually exercising unrestricted send.
- **v1.211.0** (RS-178, #506) — catalog dropdown additions (2TB SSD capacity, CAMM RAM class) plus migration `0159`. Low risk, additive.

Everything from v1.203.2 and earlier was already covered in [2026-10-04's report](./2026-10-04.md) and remains unverified in production (notably: v1.203.0's PO-manager feature and `managerChanged` 409/takeover flow, v1.201.0's Review-mode → Reviewing transition, v1.197.0's stock lock-order change, v1.195.x's public-surface rate-limiting, v1.199.0's pagination/cursor rewrite, and v1.197.1's new `CHECK` constraints).
