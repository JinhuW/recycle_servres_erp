- **`apps/backend/migrations/0172_po_ai_review.sql` (v1.245.0, RS-230 — AI review on every PO move to Reviewing).** Pure `CREATE TABLE`/`CREATE INDEX` plus one `INSERT ... ON CONFLICT DO NOTHING` seeding `workspace_settings.po_ai_review` with `enabled: false`. No backfill, no data rewrite, no hard-fail guard. Low boot risk, and the feature itself is off until a manager opts in.
- **`apps/backend/migrations/0173_po_sold_is_a_flag.sql` (v1.246.0, RS-231 — PO Sold becomes a flag, not a stage).** A single idempotent `UPDATE orders SET lifecycle = 'done' WHERE lifecycle = 'sold'`. No guard, no exception path — worst case it's a no-op on a second run.
- **`apps/backend/migrations/0174_orders_sold_lands_as_done.sql` (same release).** Adds a `BEFORE INSERT OR UPDATE` trigger that rewrites any `lifecycle = 'sold'` write to `'done'`, specifically to cover the old container instance still writing `'sold'` during the rolling-deploy overlap after `0173` ran. This is a notably careful migration — it anticipates the exact two-instances-briefly-running problem that `0169`/`0170` (flagged in prior reports) did not guard against — and carries no hard-fail path itself.
- **RS-227/RS-228/RS-229/RS-232/RS-233/RS-234 (`v1.242.0`–`v1.247.2`)** — no new migrations; these are application-logic changes (bid-sheet pricing by part number, RAM part-number cross-checks, RAM-family grouping, price-sheet import, and three rounds of pre/post-release review fixes for the same batch, per `CHANGELOG.md`).
