## Root-cause analysis

Nothing to fix in code.

- **Resume loops.** All parks were `DEAD`; the resumable ones are
  `connect_failed`, which `packages/shared/src/fleet.ts` (`fleetSlotRetirable`
  comment) treats as a proxy fault, not a lost account. `fleetAutoResumeDue`
  (`packages/shared/src/fleet.ts:70`) spaces eight tries and then returns
  `null`, and the heartbeat in `apps/backend/src/fleet/claim.ts:576-591`
  skips a try only while the proxy's latest check is fresh *and* failing.
  The four workers each came back, died within 1–60 min, and were tried
  again about hourly. From 19:02 the three still retrying (`homelab-2`,
  `worker-60-14-4`, `worker-60-14-6`) resumed within the same two minutes
  and parked again within the same two minutes, on two different hosts, so
  the cause is shared upstream (proxies or Facebook), not one host. The same
  task id showing up in two release lines a minute apart (17040, 17044,
  17102, 17500, 17592, 17192) is the queue handing the released city to the
  worker that had just resumed, which then died for the shared reason above.
- **`no_slot`** (`apps/backend/src/fleet/claim.ts`, the `no_slot` answer): no
  free fleet slot. Tickets minted: `homelab-5` 237, `homelab-8` 236,
  `worker-60-14-3` 236, none claimed. The worker exits before opening a
