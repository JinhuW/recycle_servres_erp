# Changelog

All notable changes to this project. Generated by scripts/release.sh.

## [Unreleased]

### Removed
- feat(purchase-orders)!: remove the per-PO commercial invoice PDF — `GET /api/orders/:id/invoice`, `lib/pdf.ts`, the `pdfkit` dependency and the download buttons on both the desktop orders table and the mobile order detail. The spreadsheet is the only PO download now, and it's the one that carries the line detail. Keeping both meant every new line field had to be added to two divergent `order_lines` queries, and the PDF's had already fallen behind — it never learned `chip_number` or `sell_price`. Also clears the dead `invoice*` / `invStamp*` i18n vocabulary (31 EN + 29 ZH keys, zero call sites) stranded by the client-side print-to-PDF component that route replaced

### Features
- feat(inventory): the grouped inventory spreadsheet (`GET /api/inventory/export?view=grouped`) drops its five money-and-people columns — `Cost min`, `Cost avg`, `Cost max`, `Sell price` and `Submitted by`. Grouped is the sheet that gets sent outward to vendors and buyers, and it carried per-part cost spreads on every row; the flat export keeps `Unit cost`, `Sell price`, `Profit`, `Margin %` and `Submitted by` for internal use. The grouped tail is now purely stock shape: warehouses, qty, in stock / in transit / reviewing, PO and lot counts. The desktop grouped *view* is unchanged — it reads a different endpoint (`/api/inventory/products`) and still shows the cost range to managers
- feat(inventory): serial numbers are now first-class in search — the activity feed (`GET /api/inventory/events/all`) matches on `serial_number` like the inventory list and product views already did, and both search placeholders say so ("Search part #, serial #, brand, ID…" / 「搜索零件号、序列号…」), because a searchable column nobody knows about isn't searchable
- feat(purchase-orders): serial-number rules on order lines — a DDR5 RAM line must carry serial numbers, and once serials are entered on **any** line their count must equal the line qty. Both rules live once in `@recycle-erp/shared` (`serialIssue`) and gate every save path: the desktop submit drawer, the desktop edit-order page, the mobile submit form (a blocking dialog names the offending line and keeps the form open — nothing reaches the DB), and the backend `POST /api/orders` / `PATCH /api/orders/:id` (400). Existing rows predating the rules stay editable for price/status; the check only fires when an edit actually changes serials, qty or generation. The serial field's label drops "optional" for a red "required for DDR5" tag the moment DDR5 is picked
- feat(purchase-orders): the PO spreadsheet drops the composed `Item` label column — once every attribute has its own cell it only repeated them back as an unsortable string. `poLineLabel` goes with it, leaving no composed-label code on the PO export path. The download control in the orders table's Actions column and on the mobile order detail also switches from the document glyph to the download arrow: it was the PDF button that used to carry the download icon, so removing the PDF left the surviving Excel button looking like "view file" rather than "download"
- feat(purchase-orders): the PO spreadsheet's Line items tab carries the order category's full spec set — RAM gets Part #, Chip #, Brand, Capacity, Gen, Type, Class, Rank and Speed; SSD and HDD get Interface, Form factor, Health % and RPM — instead of collapsing every attribute into one composed `Item` string. It was the last export still doing that: inventory and the vendor price template moved to per-attribute columns in July, so you could sort stock by rank but not the PO that bought it. A `Serial #` column joins the cost tail, and the `Category` column goes — an order is single-category by construction, and the Payment tab already names it. The category→column table now lives in `lib/categoryColumns.ts` shared with the inventory export, which had been its sole owner; the vendor bid sheet keeps its own copy on purpose, because its header text is load-bearing for the round-trip price import parser and must not move when this one does
- feat(purchase-orders): the manager-only stage filter moves out of its own card and into the orders table's toolbar as a row of status chips, so category, status, archived, search and columns are finally one control cluster instead of two. It was the largest element on the page and the least-used control on it; as a card it also repeated the KPI row's label-over-big-number pattern directly above the KPI row. Per-stage revenue is dropped from view (it survives in each chip's tooltip) because selecting a stage already recomputes the whole KPI row from the filtered set — the card was previewing a number the row below it was about to show. The separate "Clear filter" button goes with it: an `All` chip clears, and clicking the active chip toggles off. Chip dots now take their colour from `statusTone(label)` rather than `WorkflowStage.tone`, which disagreed on Reviewing (green vs the Status column's amber) — invisible when the two sat 200px apart, glaring once the chips landed directly above that column. That leaves `tone`, `short` and `icon` unused on `WorkflowStage`, so the type is down to `{id, label}`
- feat(activity): the Activity register loads as you scroll instead of making you press "Load older" — an IntersectionObserver on a sentinel after the last row fetches the next page a screenful early, so rows are usually already there when you reach the bottom. The column head and day rules now stay pinned while the rows move: `.ac-scroll` sets `overflow-x`, which forces `overflow-y: auto` and makes it a scroll container, so `position: sticky` inside it was clamping to a box that the *page* was scrolling away — the register now owns a bounded height and is the real scroller, matching how `.page-history` already works
- feat(activity): new manager-only **Activity** page (`/activity`, under a new "Oversight" group in the sidebar) — the first place the four audit ledgers are readable together. `order_events`, `sell_order_events`, `inventory_events` and `ref_price_events` union into one reverse-chronological register, filterable by area (purchase orders / sell orders / inventory / pricing), by action, by person, by date range, and by free text over record ids, part numbers and names. Raw kinds are normalised to one vocabulary — `advanced`, `status_changed` and `status` all read as "Status" — via a map in `@recycle-erp/shared` so the query and the labels can't drift. Laid out as an aligned five-lane register rather than the dot-and-rail timeline the per-record panels use: the diff gets its own column, so a run of price changes can be scanned straight down. Each row carries a 3px stripe naming its source ledger, which collapses to one colour as you filter. Migration 0079 adds the `created_at DESC, id DESC` feed indexes every ledger was missing — all four only indexed `(parent_id, created_at)`, so a global feed would have seq-scanned every one of them. Vendor bids and member/permission changes are absent because they write no audit rows anywhere today
- feat(purchase-orders): Chip # on a RAM line is required only for **Micron** and **Other** brands — the two whose part numbers don't identify the module on their own. Samsung, SK Hynix and Kingston lines no longer block Confirm/submit on a blank Chip #, and the label drops its `*` as soon as the brand says so. The rule lives in one place (`chipNumberRequired` in `lib/ramRequired.ts`) so the desktop drawer, the mobile submit form and both validation gates can't drift apart. A blank brand asks for nothing — brand itself is already flagged. An off-catalog brand value (legacy or imported, rendered as a one-off option) counts as neither, so it isn't asked for either
- feat(purchase-orders): "Confirm line" in the desktop edit-order drawer now writes that line straight to the database instead of parking it in local state until Save — the drawer already had the hook, the edit page just never passed it, so the button silently only closed the drawer. Confirming a brand-new line stores the id the backend hands back, and `save()`'s delete diff now tracks the live set of persisted ids rather than the page-load snapshot: without that, a line added, confirmed, then removed would have been left orphaned in the order
- feat(purchase-orders): the Submission attachments dropzone on the submit page accepts spreadsheets (`.xlsx`, `.csv`) alongside receipts, so a vendor's lot manifest or price list lands on the PO instead of staying in someone's inbox. Migration 0077 widens the stored `upload_allowed_mime` setting — `getUploadLimits` intersects it with the hard allowlist, so the constant alone would have changed nothing on a deployed database. Legacy `.xls` and macro-enabled `.xlsm` stay refused; the attachments bucket is public, so non-image uploads are now served `Content-Disposition: attachment`
- feat(inventory): the SSD capacity dropdown offers `1TB` in place of `1024GB` (migration 0078 plus the matching `seed.mjs` list). Existing records holding `1024GB` still display — the catalog select renders an unknown stored value as a one-off option
- feat(purchase-orders): the PO timeline records **everything** on a draft, with nothing filtered out. Reverses the v1.32.0 decision to drop a lone `total_cost` change while drafting — every move is logged, so building a PO shows one "Total cost" row per line appended. Also closes two paths that recorded nothing at all: `POST /api/orders/draft` (the empty-draft "New order" button) now writes its `created` event, and `serial_number` — patchable but missing from the audit allow-list — is now diffed like every other line column

### Fixes
- fix(sell-orders): the vendor bid sheet's sorting and header filter, shipped straight to `main` as hotfixes on 2026-08-06, are finally on `dev` — without this back-port the next `dev`→`main` release would have reverted both in production. Rows now leave pre-sorted the way the desk reads them (capacity, then rank, speed, brand, numerically collated so 8GB sorts below 128GB and specless manual lines sink), the packing tabs use that same order so a picker and a manager find a product in the same place, and every category tab carries an autofilter across the full header row. The workbook now ships with **no sheet protection at all** — the prod version kept a passwordless lock that a manager had to lift through Review > Unprotect before reshaping a long sheet, and it was never security. Nothing downstream cares: the import parser re-locates columns by header text and matches rows by part number, never by position
- fix(mcp): a tool that runs and fails now answers with a normal result carrying `isError: true` and a text explanation, instead of a JSON-RPC error. Only genuine protocol failures — unknown tool, `insufficient_scope`, a malformed request — stay error responses. ChatGPT relays a JSON-RPC error to the model as `{"type":"json_rpc_error",…}`, which reads as a dead endpoint rather than a bad argument: one `set_market_price` call against a part number that didn't match returned `-32602 not_found`, and ChatGPT concluded the write tool had been "disabled by the system" and refused to write prices for the rest of the session, including for parts that would have matched. `not_found` now names the part number back so the two cases are distinguishable, and both write tools' descriptions tell the client to fix its arguments and retry. Every tool also ships MCP `annotations`: without them a client applies the spec defaults (`readOnlyHint: false`, `destructiveHint: true`, `openWorldHint: true`), which is why ChatGPT's connector panel labelled all five — the three read-only ones included — "public write / destructive / open world" and gated reads behind elevated-risk confirmations
- fix(version): the settings footer and the mobile About sheet showed a 40-character commit sha next to the version — unreadable, and it answers a question nobody in the office asks. Both now show the date the running build was made ("v1.48.1 · Aug 5, 2026"), with the sha kept on the footer's hover title for deploy checks. `/api/health` gains a `builtAt` field, stamped into the image by `apps/backend/Dockerfile` (a `RUN date` layer after the source COPY) because no builder hands one in — Railway, which builds every prod deploy, passes no build args and injects no build timestamp. A host `pnpm dev` run has no image and so no date: the field is null and the UI shows the version alone
- fix(workspace): `GET /api/workspace` 403'd every non-manager, which silently pinned purchasers to the SPA's hardcoded fallbacks instead of the configured values — `auth.tsx` catches the rejection with a `console.warn` and carries on, so a manager setting `low_health_pct` to 70 left purchasers still seeing 50, the exact divergence migration 0025 existed to remove. The endpoint now filters by key (`PURCHASER_VISIBLE_SETTINGS`) rather than rejecting the request; pricing, upload and notification keys stay manager-only, so the original security intent holds
- fix(auth): a 401 from `POST /api/auth/login` was treated as an expired access cookie, so every mistyped password fired a refresh that could never succeed and then dispatched `auth:unauthorized`, wiping the already-loaded lookups/workspace caches. `isSessionEndpoint()` now exempts login alongside refresh — an endpoint whose job is to *establish* a session must never be wrapped by the 401→refresh→retry path
- fix(purchase-orders): receipt auto-rename shipped every non-PDF attachment to OpenRouter as image bytes — it guarded on `application/pdf` rather than checking for an image. A spreadsheet upload would have paid for a guaranteed-useless vision call; the guard is now a positive `image/*` check
- fix(purchase-orders): the Activity panel was permanently empty on Draft POs — every audit write was gated behind `lifecycle !== 'draft'`, a guard that existed only because the append-only trigger used to block the draft-delete cascade (migration 0038 fixed that long ago). Drafts are now audited like every other stage, so edits, line add/remove and Done-evidence show up while the order is still being prepared

- fix(purchase-orders): building a draft no longer buries its timeline — the submit form re-sends the running `totalCost` with every line it appends, which logged one "Total cost: $X → $Y" row per line (a 30-line PO produced 29). A lone `total_cost` delta on a draft is that recompute, not a decision, so it isn't recorded
- fix(frontend): an order event whose kind the loaded bundle doesn't know (backend and Worker deploy independently) rendered `undefined` and threw, unmounting the whole app — there is no ErrorBoundary. Unknown kinds now degrade to the raw kind name
