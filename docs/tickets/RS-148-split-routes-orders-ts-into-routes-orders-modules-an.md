## Context

`apps/backend/src/routes/orders.ts` had grown to 3,632 lines holding 24
routes. It mixed the list, the detail, creation, the 900-line PATCH, the
lifecycle moves, evidence uploads, Review mode and the spreadsheet. Inside its
transactions, refusals were thrown as message strings (`'__DONE_LOCKED__'`)
and matched with `includes()` in a catch block. Their payload went through
variables captured from the handler.

## Acceptance criteria

- [x] `routes/orders/` holds `index.ts` plus one module per concern: `list`,
      `detail`, `create`, `patch`, `lifecycle`, `evidence`, `checks` and
      `spreadsheet`. Each is a Hono sub-app. Helpers two modules share live in
      `shared.ts`.
- [x] The code moved verbatim, apart from the router variable each route
      registers on and the import paths.
- [x] `OrderRefusal` (`refusal.ts`) with a typed `kind` and payload replaces
      every `__SENTINEL__` string in PATCH, the status-meta attachments and the
      line photos. One `refusalResponse` maps them to the same status codes and
      bodies as before.
- [x] Every existing backend test passes unchanged.

## Out of scope

- Moving the PATCH transaction into `services/orderPatch.ts`. With PATCH in a
  module of its own, the further extraction would mostly thread a dozen
  handler-scoped values through a function signature, for no gain in what a
  reader has to hold in their head.

## Notes

- The split was generated by a script that took the line ranges of the old
  file and computed each module's imports from the identifiers it uses. Every
  cross-module reference resolved into `shared`, so no route module imports
  another.
