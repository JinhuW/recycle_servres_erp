## RS-313: make the Playwright waits real

**Rule.** Where the code expects an element to appear after a navigation or submit, use `locator.wait_for(state="visible", timeout=N)` inside the existing `try/except Exception` (a `TimeoutError` is already handled as "not visible" at every site). Where the code checks current state, call `is_visible()` with no argument so it says what it does. No new helper: there is no shared one today and the monitor cannot import rs_poster.

| Call | Change |
|---|---|
| `session.py:334` `_accept_cookies` | wait 5000, add `.first` (strict-mode risk without it) |
| `session.py:386` `_handle_two_factor` trust button | wait 5000 |
| `session_cli.py:143` trust button | wait 3000 |
| `poster.py:246` `_publish` Next button | wait 4000 |
| vendored `facebook.py:1295` `trust_this_device` | wait 5000 |
| vendored `facebook.py:997` Allow-cookies button in `login` (no timeout today, log text says "within timeout") | `.first` + wait 3000 |
| vendored `facebook.py:1383` locked-account text when URL already says checkpoint | wait 2000 (a miss misreports a locked account as a plain checkpoint) |
| `session.py:127` `raise_if_restricted` | snapshot: drop the argument. Runs on every navigation; the banner is an interstitial that persists, so the next navigation catches a miss, and a real wait would add 1 s to every healthy page |
| `session_cli.py:117` 2FA field in the capture poll loop | snapshot: drop the argument (loop already sleeps 3 s) |
| vendored `facebook.py:1397,1405` captcha iframe/text in `detect_login_challenge` | snapshot: drop the argument. Three selectors × 2 s would add 6 s to every failed-login check, and the decision-model fallback from RS-311 now covers what the selectors miss |

## RS-314: only ack a reply the pane shows as sent

**Why snapshot-diff.** Direction `out` comes from Facebook's "You sent" accessibility copy, which neither the composer draft nor the thread-list preview carries, and `div[role="main"]` already excludes the list. Counting *new* out-rows against a pre-typing baseline also defeats the older-identical-bubble case, which no `get_by_text` scoping can. The diff is pure Python, so it is testable without a browser.

**Sender** (`rs_messenger/rs_messenger/sender.py`):
- Pure helpers: `make_probe(text)` (first 60 chars, whitespace-collapsed), `count_out_rows(rows, probe)`, `already_sent(rows, probe)`, `reply_landed(before, after, probe, composer_text)` = more out-rows containing the probe than before **and** the probe is no longer in the composer. Text comparison is whitespace-normalised and casefolded.
- `_snapshot(page)` runs the existing `EXTRACT_MESSAGES_JS` (`selectors.py:53`), the same read `inbox._read_thread` uses.
- Flow: locate composer → `before = _snapshot(page)` → if `already_sent(before, probe)`: log and return `(True, None)` without typing (**idempotency guard**: a lost ack re-fetches the row, the sender sees its own bubble, no duplicate) → click/type/Enter → poll `reply_landed` every 0.5 s for up to 15 s.
- On timeout, inspect the composer:
  - probe still there (Enter did not submit): `Control+A`, `Backspace` (the messenger runs in the Linux worker image), re-read, return `(False, "reply not submitted; composer cleared")`. Clearing keeps the retry from doubling the text.
  - composer empty but no new out-row: `(False, "sent text did not appear as an outgoing bubble")`. If it did land, the retry's `already_sent` resolves it as sent.
  - Error strings become module constants; "composer not found" is reported as permanent (see below).

**Coordinator** (bounded retry, no lease: one sequential sender per account and ≥60 s pacing make concurrent drains of one row impossible):
- `OUTBOUND_MAX_ATTEMPTS = 3` in `db.py` beside `OUTBOUND_EXTRA_COLUMNS`, imported by `pg.py`.
- `mark_outbound(id, status, error=None, permanent=False) -> str` returns the effective status. `failed`: one statement, `status = CASE WHEN ? OR attempts + 1 >= ? THEN 'failed' ELSE 'queued' END`, `attempts + 1`, `last_error`, with `AND status <> 'sent'` so a late failure never demotes a sent row. `sent` as today. Identical SQL in `pg.py:546`.
- `OutboundAck` (`schemas.py:175`) gains `permanent: bool = False`; the handler (`routers/messages.py:163`) returns `{"status": "ok", "outcome": <effective>, "attempts": n}` and the sender logs "requeued" vs "failed". Old clients that omit the field keep working.
- `rs_router/cli.py:153` passes `permanent=True` for Matrix errors (forbidden room, bad token do not fix themselves); rows it cannot deliver yet stay unacked as today.

**Tests.**
- New `rs_messenger/tests/test_sender.py`: pure-helper cases (new out-row → landed; only match predates typing → not; matching row tagged `in` → not; probe still in composer → not; `already_sent`; normalisation; probe truncation). A ~60-line `FakePage`/`FakeLocator` (goto, wait_for_load_state, get_by_role/locator → `.first`, count, wait_for, click, type appending to a composer buffer, inner_text, keyboard.press recording keys, evaluate popping scripted snapshots) with `human_pause`, `time.sleep`, `raise_if_restricted` and the verify timeout monkeypatched. Scenarios: happy path; Enter swallowed → composer cleared, `Control+A`/`Backspace` recorded; pre-existing identical bubble plus swallowed Enter → False (the regression test for today's bug); `already_sent` → True with zero `type` calls; composer missing → permanent error.
- `rs_coordinator/tests/test_messages.py`: failed ack keeps `queued` with `attempts=1`; three failures → `failed` and `pending_outbound()` empty only then; `permanent` skips the retries; a failed ack never demotes `sent`. Parity: `test_outbound_retry_cap` in `test_postgres.py` on the `backend` fixture.

## RS-315: keep challenge screenshots on the volume

- `escalation.py`: anchor the default next to the database, mirroring `db.default_db_path()`: default = `Path(default_db_path()).parent / "screenshots"` (so a local run writes under the checkout's `data/`, the container under `/data/`). `RS_SCREENSHOT_DIR` still wins.
- `deploy/Dockerfile.coordinator`: `ENV RS_SCREENSHOT_DIR=/data/screenshots`. `deploy/docker-compose.coordinator.yml`: same under `environment:` so the compose file says what the comment on the volume already claims.
- `save_screenshot` stores an absolute path.
- Challenge list (`escalation.py:237`): set `screenshot_url` only when the file exists, so the ERP's "No screenshot captured" fallback is honest rather than a 404 after the fact.
- Tests (`rs_coordinator/tests/test_escalation.py`): default with no env resolves under the DB directory and is absolute; list omits `screenshot_url` for a missing file. Document the variable in `configs/secrets.env.example` (commented) and README's coordinator section.
- Deploy verification: after `deploy.sh`, `docker exec rs-coordinator sh -c 'echo $RS_SCREENSHOT_DIR; ls -ld /data/screenshots'`.
- Out of scope: retention (challenges are a few a week, PNGs under 1 MB); recovering past screenshots (gone).

## RS-316: shadow-run a listing pre-screen

- **Vendored `monitor.py`** `ai_eval` event (~line 279): add `unit_count=res.unit_count`, `quantity=res.quantity`, `model=<configured model id>` so future replays carry the unit-count label. Additive fields only.
- **New `scripts/prescreen-shadow.py`** (follows `fleet-verify.py`: stdlib, `RS_OPENSEARCH_URL`, run on the VM or through an ssh tunnel to `127.0.0.1:9200`):
  - Pull `ai_eval` events for `--days N` (default 14), `cached:false` only, dedupe by `listing_id`; stratified sample: every event with score ≥ 3 plus `--sample 1500` of score 1–2.
  - For each, one `choice` question on the Decisions API (reuse the request/parse shape from `page_state.py`: model from `--model`, default `openai/gpt-6-luna-decisions`; labels `reject` / `maybe` / `buy` with the production rating prompt's wording from `configs/master.toml:408`), state = item name + title + price + description.
  - Report: per threshold on P(reject), the share of billed calls saved and the recall of score ≥ 4 and of score ≥ 3; latency and `usage.cost` totals; the listings a threshold would have dropped that scored 4+, with URLs. Markdown to stdout, like `sweep-report.py`.
  - Run it twice (two models: Luna Decisions and Jev) and paste the tables into the ticket.
- **Go/no-go rule written into the ticket:** proceed to a live gate only if some threshold keeps ≥ 99% of score-4+ listings while dropping ≥ 50% of billed calls. The gate itself (a `RS_PRESCREEN_MODEL` env var, `listing_skip reason=prescreen`, off by default) is a follow-up ticket, not this one.
