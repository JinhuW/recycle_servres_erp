## Confirmed findings

- [ ] **FE-01 · P1 — Reset order/capture data when the authenticated identity changes.** Evidence: `apps/frontend/src/DesktopApp.tsx:58`, `:98`, `:125`, `:199`, `:251`; `apps/frontend/src/MobileApp.tsx:143`, `:176`, `:212–238`; `apps/frontend/src/lib/auth.tsx:10–15`. The shell persists above the login gate. Desktop PO loading only depends on `path`, and neither logout nor the next login clears `editingOrder`. If a manager's session ends while a PO is open, another purchaser signing in under that unchanged hash gets the previous manager's PO object (including private notes) without a new authorized GET. The same pattern retains mobile capture state across an unauthorized-session/login transition. The backend still guards writes; the confirmed issue is disclosure of already-fetched data in the browser. **Fix:** key authenticated shell state by session/user identity, clear all retained records and pending capture/photo work on logout, invalidate in-flight callbacks, and refetch under the new identity/effective access scope. **Regression:** manager opens another user's PO → session becomes unauthorized → different purchaser logs in; no previous PO data may render, even before the new GET settles. The source-extracting desktop hook probe demonstrates disclosure and exactly one GET across both identities.

- [ ] **FE-02 · P1 — Finalizing a mobile PO must await its line autosaves.** Evidence: `apps/frontend/src/MobileApp.tsx:475–478`, `:536–558`, `:678–717`; `apps/frontend/src/pages/OrderReview.tsx:56–88`, `:178–190`; `apps/frontend/src/lib/orderSubmit.ts:80–112`. Saving a new line immediately opens Review while its draft POST/line PATCH is still pending. Submit neither waits for that work nor knows the line is already being inserted. If the draft ID is present, Submit appends the same unconfirmed line a second time; if draft creation is still pending, it can create a second PO. These are independent requests, so normal server transactions do not deduplicate them. A slow mobile connection makes the window easy to hit. **Fix:** put per-session/per-line writes in a serialized queue, await the pending draft and autosave before finalization, use the resulting latest state, and use stable idempotency keys where creation can be retried. **Regression:** defer draft creation and defer a new-line PATCH separately, press Save then Submit, and assert one PO with exactly one line. The probe runs the actual callbacks with a delayed PATCH and records two identical `addLines` requests.

- [ ] **FE-03 · P1 — Failed mobile edits of already-confirmed draft lines must remain retryable.** Evidence: `apps/frontend/src/MobileApp.tsx:459–477`, `:484–516`; `apps/frontend/src/lib/orderSubmit.ts:97–112`. Resume a draft or edit an autosaved line, change its cost/specs, then let its PATCH fail. Review already holds the modified line with `_confirmed: true`; the catch only displays an error. Final Submit filters that line out and can return `noop`, then navigates away as if the changed order were submitted. The changed values never reached the server. Simply clearing `_confirmed` is insufficient because the submit builder treats all unconfirmed lines as **new** inserts. **Fix:** explicitly track persisted-but-dirty lines and failed writes, retain the form or pending edit on failure, and retry existing lines with their IDs before completion. **Regression:** fail an existing-line PATCH, retry through final Submit, and assert the original row is updated once with no duplicate row. The probe confirms local cost changes from 5 to 7 while final submission is `noop`.

- [ ] **FE-04 · P2 — Reconcile installed-app shortcut URLs with the hash router.** Evidence: `apps/frontend/src/lib/route.ts:19–28`, `:516–525`; `apps/frontend/vite.config.ts:89–96`; `apps/frontend/src/lib/shellPaths.ts:21–30`; `apps/frontend/src/MobileApp.tsx:126–137`. The manifest launches `/submit`, `/inventory`, and `/sell-orders` as real paths. The edge/SW explicitly serve those shell paths, but `readPath()` accepts only `/authorize` outside the hash and otherwise returns `/`; the shortcut silently lands on Dashboard. `/submit` is also not a mobile route that opens capture, so changing the manifest to a hash alone does not implement the phone Submit shortcut. **Fix:** define one intentional contract for real-path launch URLs versus hash routes and make mobile Submit explicitly enter its capture flow. Preserve the OAuth real-path exceptions. **Regression:** launch each manifest URL as a cold document with no hash, verify the expected screen/role behavior, and test both shells. The probe confirms `/inventory` resolves `/`.

- [ ] **FE-05 · P2 — Complete the Web Share Target image handoff.** Evidence: `apps/frontend/src/sw.ts:39–48`; `apps/frontend/src/pages/ShareTarget.tsx:8–40`; `apps/frontend/src/MobileApp.tsx:729–733`; `apps/frontend/src/DesktopApp.tsx` has no share-target branch. The share-target POST handler calls `Response.redirect()` with a relative URL; that constructor rejects it with `TypeError`, so sharing an image fails before navigation. Independently, `/share-target` is discarded by `readPath()` (FE-04). Even if those are fixed, the handoff writes `sessionStorage['pwa:sharedFile']`, but there is no reader anywhere in current source; it then navigates to `/submit`, which does not open capture on mobile. The comments claiming LineDrawer consumes the image are not backed by code. **Fix:** build an absolute redirect from the request URL, route the landing in the intended shell, and actually consume/clear the image into the scan/capture flow with a cancellation/error path. **Regression:** installed app shares an image while authenticated and while logged out, and the exact file arrives at the scanner once after login. The constructor failure is reproduced; a repository-wide key search verifies the absent consumer. A real installed-browser smoke test remains needed after a fix.

- [ ] **FE-06 · P2 — Serialize preference writes and ignore replies from earlier sessions.** Evidence: `apps/frontend/src/lib/preferences.tsx:101–151`, `:153–176`. `flush()` starts a new PATCH even when `inflightRef` is set; the ref is recorded but never awaited. Each reply replaces the entire preferences bag and local cache. Two edits separated by the 400 ms debounce can therefore settle out of order, and the older response overwrites the latest choice. A response started for user A can also replace user B's freshly reconciled preferences after a login. Failure rollback similarly has no revision/session guard. **Fix:** serialize batches, preserve newer optimistic edits when merging server replies, and tag work by authenticated identity plus per-key revision; cancel pending timers on logout/identity change. **Regression:** resolve two real-provider mocked PATCHes newest-first and verify the latest choice remains; switch user before an older response returns and verify no old-user preferences apply. Both are demonstrated by the probe using the actual provider function.

- [ ] **FE-07 · P2 — Persist inventory internal notes or remove the editable field.** Evidence: `apps/frontend/src/pages/desktop/DesktopInventoryEdit.tsx:133`, `:208`, `:280`, `:1025–1037`; `apps/frontend/src/lib/inventoryEditPatch.ts:36–62`. “Internal notes” is an editable textarea backed only by `useState('')`. It is never seeded from the API, does not participate in dirty detection, and is not in the save body. Typing only a note leaves Save disabled; editing another field and successfully saving still drops the note. **Fix:** add a real backend note field/endpoint and include it in read/save/dirty tracking, or remove the input until persistence exists. **Regression:** enter a note, save, reopen the same item, and verify the note persists; note-only edits must enable saving. Confirmed by tracing every reference to `internalNotes` and the patch builder.

- [ ] **FE-08 · P2 — Register inventory edits with the shared unsaved-change guard.** Evidence: `apps/frontend/src/pages/desktop/DesktopInventoryEdit.tsx:208–215`, `:313–344`, `:436–447`; `apps/frontend/src/DesktopApp.tsx:230–236`; `apps/frontend/src/lib/unsavedGuard.tsx:29–47`. The inventory page computes/displays `dirty` but never calls `useUnsavedGuard`; its Back/Cancel handlers navigate immediately. Sidebar links, browser history, reload and the shell layout switch therefore discard edited quantity, price or specs without the discard confirmation used by PO/sell-order editors. **Fix:** register dirty state before early loading returns through a consistently ordered hook, and use `confirmDiscard` for the local Back/Cancel actions. **Regression:** edit a price, exercise Sidebar, Back, Cancel, reload and layout switch, reject the prompt, and verify values remain. Source audit confirmed no guard in this component.

- [ ] **FE-09 · P2 — Do not report a capped keyset walk as a complete PO dataset.** Evidence: `apps/frontend/src/lib/keysetPages.ts:15–21`; `apps/frontend/src/pages/Orders.tsx:64–80`; `apps/frontend/src/pages/desktop/DesktopOrders.tsx:213–229`; backend PO endpoint clamps `limit` to 200. The helper stops after 25 pages and sets `done: true` even when the server supplied another cursor. Both PO lists request 200 per page and compute search/counts/desktop totals over that array, so more than 5,000 matching POs silently disappear and figures are presented as complete. The comment that `maxPages` “never” bounds a real list is incorrect. **Fix:** exhaust the cursor with repeated-cursor detection, or expose pagination/truncation and compute organization aggregates on the server. **Regression:** return 26 nonempty pages, require the final page to be reachable, and require “complete” only when `nextCursor` is null. The probe reproduces stopping at page 25 with a live cursor; backend max was independently checked by the domain reviewer.

- [ ] **FE-10 · P2 — Contain keyboard focus in the common modal and phone-sheet layers.** Evidence: `apps/frontend/src/components/Modal.tsx:37–69`; `apps/frontend/src/components/PhSheet.tsx:17–28`; `apps/frontend/src/components/Combobox.tsx:122–135`. Keyboard users can tab to the page behind an open workflow dialog and activate background navigation/actions while the modal remains visually open. This is source-confirmed; browser/assistive-technology validation has not been run.

- [ ] **FE-13 · P2 — Follow the mobile inventory cursor instead of showing only its first page.** Evidence: `apps/frontend/src/pages/Inventory.tsx:52–62`; `apps/backend/src/routes/inventory.ts:788–838`. ## Validation and structure

`node docs/review-2026-10-13/frontend-probes.mjs` currently passes ten scenarios documenting buggy behavior in the current source. It executes extracted current functions/callbacks with controlled delays; it does not reproduce the code into a replacement implementation. It touches no external services. The parent reviewer owns the frontend suite, typecheck and production build results. Existing frontend tests primarily exercise pure helpers; passing them does not cover these React session/capture/installed-app interactions.

The shared package is a useful boundary: canonical part/serial/category rules, spec cascade, price semantics and report ranges are reused across backend/frontend, which limits drift. API CSRF headers, httpOnly cookie use, single-flight refresh plus Web Locks, lazy page chunks, several stale-response guards, and a persisted review/packing save queue are positive structural choices. No new confirmed bug was found in the 24 shared modules during this pass; hardware decoder accuracy outside the checked schemes/fixtures is not independently certified.

The main structural risk is ownership of asynchronous state. MobileApp contains its own optimistic autosave/finalization protocol while desktop has a separate save queue, and user identity is not part of retained-shell/request ownership. Major desktop editors also mix transport, workflow gates, derived finance, photo persistence and JSX in files over 1,200–2,200 lines. Size alone is not a defect; the reproduced races are evidence that these boundaries need separation.

- [ ] Extract authenticated-session-owned state and request lifecycle/epoch handling into one boundary used by both shells; apply FE-01/FE-06 consistently to caches, records and pending work.
- [ ] Extract one persisted PO capture/edit state machine with explicit pending/saved/failed states and stable line IDs, used by both desktop and mobile; implement FE-02/FE-03 there.
- [ ] Add a small rendered integration-test layer for login identity changes, deferred capture writes, router launches and shared modal focus. Keep existing pure-helper tests, but do not treat them as coverage of the UI state machine.
- [ ] Maintain one launch/route manifest for edge allowlists, service-worker fallback, PWA shortcuts and both shell routers; exercise complete handoffs, not just pathname classification (FE-04/FE-05/FE-12).
